# 按天在岗摘要：设计规格

## 目标

在「在岗时间」的按天视图中，用一张简洁摘要卡回答同事核对工时时最常见的问题：当天累计多久、几点到岗、几点下班、是否加班。移除分段明细和解释性长文，避免用户把统计页当作考勤明细。

## 界面

- 延续当前日期导航、累计在岗时长和与前一天比较。
- 在累计时长下方显示三列指标，文案固定为「到岗时间」「下班时间」「加班时长」。
- 不显示「在岗明细」、在岗片段列表、片段数量或数据规则说明文字。
- 当天仍有开放在岗片段时，第二列显示「仍在岗」；历史日期仍有开放片段时显示「记录未结束」，且累计不显示数值，避免把不完整记录当成工时。
- 未产生实际在岗记录时，三个指标显示「未记录」，累计展示沿用既有回退规则以兼容旧数据。

## 数据规则

- 到岗时间取当天倒计时的 `work_sessions.started_at`，因此会与主卡片的「XX:XX 到」保持一致；启用到工位缓冲时，该时间已按缓冲分钟回拨。没有真实在岗片段时仍不展示虚构时间。
- 下班时间取全部片段均已封存时最后一段的 `endedAt`；当天有开放片段时不展示暂定时间，以「仍在岗」表示。
- 在岗累计使用所有封存片段，加上当天开放片段从 `startedAt` 到 `now` 的时长，并额外补入倒计时起点到首段真实在岗的正向缓冲；睡眠、熄屏与关机的间隔不计入。
- 加班时长为 `max(0, 含缓冲的在岗累计 − 当天存档的 plannedSeconds)`；尚未超过基础工作时长时显示「—」，不显示负数或“还差”。
- 显示所用的 `plannedSeconds` 取 `work_sessions` 中随当天开始写入的值，避免用户后来改了基础工时而改变历史结果。
- 当天首次写入的 `plannedSeconds` 同样锁定；当天开始后修改全局基础工时只从下一次开始上班生效。
- 幸福指数读取已封存记录时采用与在岗页相同的缓冲补时，避免两页对同一工作日得出不同的加班时长。

## 实现边界

- 在 `ScreenTimeView` 中从 `ActivityStore.officePresenceSegments(workday:)` 派生按天摘要值；不改动 SQLite schema、在岗记录触发时机或已有的片段累计逻辑。
- 新增一个纯数据展示辅助类型，让首段、末段、当前开放状态、累计与加班计算可以独立测试。
- 旧版只有倒计时记录、没有真实在岗片段的数据继续使用现有总时长回退，但不虚构到岗、下班或加班时刻。

## 验收与测试

- 单段封存记录显示正确的到岗、下班、累计和超过计划的加班时长。
- 多段封存记录取最早起点、最晚终点，并以片段之和计算加班，不把间隔算入。
- 当天开放段显示「仍在岗」，累计持续增长，且不显示下班时间。
- 无真实片段的历史记录三个指标均为「未记录」。
- 计划内、等于计划和超过计划三种场景均验证加班展示。
- 运行 `./Tests/run.sh` 与 `./build.sh`，并重启本地 App 检查设置面板布局。
