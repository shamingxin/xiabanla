# 待机时钟倒计时样式设计

## 目标

在主倒计时卡片中新增「待机时钟」样式，复刻 iPhone StandBy 大时钟的视觉语言，用于 `时:分:秒` 三组倒计时；保留现有「翻页」「灵动岛」样式和所有业务计算逻辑。

## 范围与边界

- 只影响 `CountdownCardView` 的倒计时数字区及「外观」页样式预览。
- 不改工时、倒计时计算、菜单栏文本、今日工作面板、卡片外框、状态标题、进度条或已下班业务规则。
- 新样式名称为「待机时钟」，`UserDefaults` 保存为新枚举 raw value；旧用户已保存的「翻页」「灵动岛」值保持不变。
- 样式切换及三种样式的数字区占位宽度必须完全一致，卡片不可横向跳动。

## 视觉规范

- 三组两位数字按 `HH:MM:SS` 横向排布；每一组占用 `Metrics.tileSize` 的固定宽度与高度，组间分隔占用 `Metrics.tileGap`。
- 暗色模式使用近黑数字区底色。每组十位为深蓝、个位为浅蓝；两个独立的大号数字以负间距轻微交叠，并分别带轻微反向倾角，静止时不绘制复制字或投影。
- 数字使用系统圆体、等宽数字、重字重。数字不使用翻牌底板、描边或阴影。
- 每个冒号由两个较大的圆点构成，使用低对比度白灰渐变；其自身固定在组间居中，不跟随数字平移。
- 浅色模式仍按当前卡片浅色配色工作：数字改为相应深蓝色阶，交叠仍清晰，不引入固定黑底。
- 预览缩略图固定显示 `08:42:16`，必须表达深蓝十位、浅蓝个位与白灰冒号，不负责模拟运行时动画。

## 动效规范

- 每个两位数字组独立响应其 `value` 变化。秒组每秒触发；分钟、小时仅在其实际值变化时触发。
- 一次更新持续约 0.4 秒：旧的双色数字组向上滑出并淡出，新的同色规则数字组从下方接位。更新开始时，整组先横向压缩至 94%、纵向拉伸至 108%，随后以高阻尼 spring 回到原比例，形成短促有重量感的「duang」反馈；系统开启减少动态效果时直接替换数值。
- 动画采用无回弹的缓出曲线；不得使用现有 `BounceDigitGroup` 的缩放、spring 或整体上跳。
- 若上一次动画尚未结束又收到下一次值，当前可见状态立即成为下一次动画的旧值，再开始新过渡；不得堆积 `DispatchQueue` 延迟任务或闪回过期数字。
- `--` 未开始状态和已下班计时同样使用该样式；已下班沿用现有绿色状态色，不强行改成蓝色。
- 辅助功能标签继续按「值 + 小时/分钟/秒」读取；纯视觉的双色数字和冒号不应重复被读出。

## 架构

1. `CountdownStyle` 增加 `standbyClock` case，持久化路径复用现有 `countdownStyle`。
2. `CountdownCardView` 为新 case 组合三份 `StandbyDigitGroup` 与两份 `StandbyColonSeparator`；两者共享现有 `Metrics` 的固定占位。
3. `StandbyDigitGroup` 保持 `displayedValue` 和 `outgoingValue`，以 token 或可取消的 `Task` 管理一次过渡，避免秒级更新与异步完成回调相互覆盖。
4. `CountdownStylePreview` 增加相应的静态分支。现有 `CountdownStylePicker` 已遍历枚举，不需要新增选择器逻辑。

## 验收与验证

- 纯逻辑测试：新枚举出现在可选样式中，默认仍为翻页，已保存的「灵动岛」值仍能恢复。
- 构建：`./build.sh` 成功生成并签名 App。
- 现有自动计时回归：`./Tests/run.sh` 全部通过。
- 视觉人工验收：在深色和浅色下切换三种样式，卡片宽度不变；连续观察至少 10 秒，秒组只做流动过渡、不缩放回弹、无闪烁或数字回跳；跨分钟时分钟组同样平滑更新。
